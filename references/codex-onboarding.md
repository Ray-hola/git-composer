# Codex 新手入口

这份说明面向只会使用 Codex、不想先学习终端或 Git 的使用者。维护者命令仍保留在仓库内部，但普通使用者只需要把意图告诉 Codex。

## 1. 从 GitHub 交给 Codex

把下面这句话和仓库链接一起发给 Codex：

```text
请从 https://github.com/Ray-Hola/git-composer 安装并启用 git-composer。
安装前先告诉我目标位置、会改哪些文件和需要我确认的事项；不要自动提交或推送。
安装后用一句话说明我可以让它做什么，并等待我的第一个任务。
```

如果 Codex 能访问仓库，它应先报告安装范围、版本/分支事实和潜在冲突，再等待确认。没有得到确认时，不能覆盖已有 Skill，也不能创建提交。

## 2. 从 Skill 管理界面安装

如果当前 Codex 客户端提供 Skill 管理界面，选择“从 GitHub 仓库安装”，填入：

```text
Ray-Hola/git-composer
```

界面名称和按钮可能随宿主版本变化；README 不把某个未核实的按钮文字当成固定 API。找不到该入口时，回到第 1 节的自然语言方式。

## 3. 第一次任务

安装完成后，可以直接发送：

```text
使用 $git-composer 先只读检查这个仓库。
保留我现有的改动，告诉我最值得先修的 3 个问题；先不要修改、提交或推送。
```

第一次成功的判据是：Codex 报告了目标仓库、分支、工作区状态、实际证据、未验证项、风险和下一步，并明确没有执行写入动作。

## 4. 让它修改仓库

确认方案后再说：

```text
按刚才确认的范围修改。
每轮先告诉我改了什么和如何验证；未决问题先问我，全部答案确认后再提交。
```

需要提交或推送时，明确说出目标仓库、分支和副作用。Codex 应在最后一个不可逆动作前再次确认，并分别报告本地提交、推送和远端读回。

## 5. 出现问题时

可以说：

```text
停止写入，保留当前改动。
告诉我哪些命令已经运行、哪些仍未验证，以及最小恢复步骤。
```

如果你不熟悉术语，直接描述目标即可，例如“我想让 README 更容易看懂，但不想动现有代码”。Skill 会先把需要你决定的选择翻译成问题。
