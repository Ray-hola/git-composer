# 状态与变更报告模板

这些模板用于对话、Issue、PR 描述或交接记录。只填有证据的内容；没有证据就标为“未验证”。持续任务沿用同一组字段，避免把计划、已完成和待验证混在一起。

## 1. 状态

```text
状态：已完成 / 部分完成 / 被阻塞
范围：<文件、分支或远端对象>
基线：<起始提交、分支和工作区状态>
改动：<实际改了什么，以及对使用者的影响>
验证：<命令> → 通过 / 失败 / 未验证
证据：<路径、行号、提交或页面链接>
风险与恢复：<风险；如何回退或恢复>
未知：<仍待确认的事实；没有则写“无”>
下一步：<一条最有价值的动作>
```

## 2. 变更

```text
文件/对象：<路径、分支或远端对象>
原因：<对使用者的影响>
变更：<实际改了什么>
保留：<确认保留的既有内容或用户改动>
未触碰：<明确排除的范围>
```

每个文件只说明和用户有关的目的；不要把计划中的文件写成已修改，也不要把无关的既有改动混入本轮变更。

## 3. 进度消息

长任务每个阶段只更新一次：

```text
进度：已完成 <动作>；正在做 <唯一下一项>；阻塞：<没有 / 明确缺口>
基线：<分支、工作区状态或上一次验证结果>
保留：<用户已有改动或未触碰范围>
累计证据：已核实 <去重文档数>；候选项目目标 10,000+：pending / 已完成（附来源）
最近检查：<命令> → 通过 / 失败 / 未验证
下一次更新：<完成条件或停止条件>
```

“正在做”不等于“已通过”；命令尚未退出时不能写成功。遇到权限、网络、目标分支或业务决策阻塞时，保留已经完成的本地结果，并写出恢复所需的最小信息。

## 4. 证据

```text
标签：已核实 / 已修正 / 待决定 / 未验证 / 不适用
事实：
来源：<命令输出、文件:行号、固定提交链接或页面>
时间：<必要时填写>
限制：<采样、权限、网络或页面可见性限制>
```

按对象区分证据强度：

- **文件事实**：路径、行号或机器可读字段直接存在。
- **命令结果**：给出完整命令、退出码和关键输出；只说明实际运行的环境。
- **配置声明**：workflow、模板或文档写了什么；不能代替远端运行成功。
- **远端结果**：提交、CI、发布或页面从同一目标读取并核对。
- **未验证**：缺少权限、网络、目标环境、固定 SHA、内容哈希或视觉预览时明确写限制。

候选样本、搜索命中、元数据记录和部分读取不等于完整研究；有多个计数口径时同时写“尝试数 / 成功数 / 去重数 / 排除数”。

## 5. 验证

```text
命令：<完整命令，必要时包含工作目录>
预期：<成功标准>
结果：通过 / 失败 / 未验证
退出码：<数字或“未运行”>
输出摘要：<关键结果；不要粘贴凭据或大段日志>
未覆盖：<例如远端运行、视觉预览或目标仓库业务测试>
```

文件生成、本地命令通过、远端工作流通过和公开页面可见是不同结果，分别报告。不要用“命令已执行”代替“结果通过”。

## 6. 风险与恢复

```text
风险：<可能发生什么>
触发条件：<何时会发生>
当前保护：<备份、未触碰范围、分支或检查>
恢复步骤：<可复制命令或明确人工动作>
恢复前提：<备份、提交、权限或目标确认>
```

未提交的改动只在确认路径和内容后回退；已提交的共享改动使用 `git revert`，先核对目标提交、分支和远端状态。不要只写“撤销即可”，也不要宣称 reflog 能找回从未提交的全部文件。

## 7. 提交与远端回执

```text
本地提交：<短哈希> <标题> / 未提交
目标远端：<实际 URL 或“未确认”>
目标分支：<实际分支或“未确认”>
推送：已推送 / 未推送 / 失败
远端核验：<读取到的远端提交、页面或“未验证”>
范围门禁：<文件清单已核对；敏感数据检查结果>
```

只有从目标远端读取到预期提交或页面后，才填写“远端核验：已验证”。“本地 commit 已创建”“推送进程成功”和“从远端读回目标提交”必须分别有证据。

## 8. 未知、下一步与停止条件

```text
未知：<不能从现有证据判断的事实>
需要谁决定：<用户 / 仓库维护者 / 远端管理员>
下一步：<一条最小、可审查的动作>
停止条件：<出现什么就先停>
```

## 9. 最终交付块

持续更新和最终交付都按“状态与范围 → 改动与原因 → 证据与计数口径 → 验证命令与结果 → 风险、恢复与保留项 → 未验证或待决定 → 下一步和停止条件”的顺序，除非用户要求其他格式。长日志放在可追溯位置，正文保留能帮助用户决定下一步的摘要。

```text
状态：已完成 / 部分完成 / 被阻塞
变更：<文件与用户可见影响>
保留：<既有改动、未触碰范围>
验证：<命令> → <通过 / 失败 / 未验证>；未覆盖：<维度>
证据：<路径:行号、固定提交、远端读取或页面链接>
风险：<触发条件与影响>
回滚：<可复制命令、提交或补丁；恢复前提>
提交：<commit 或“未提交”>
远端：<remote/branch、推送回执或“未执行”>
未知：<待决定事实；没有则写“无”>
下一步：<一条最有价值的可审查动作>
```
